# 工作卡片 · 详细说明

给 DeepSeek Harness（DSH）加一层桌面可见的"会话状态面板"。每个活跃会话一张置顶卡片，不用切回 DSH 就知道它在干什么、走到第几步、卡没卡。

## 卡片长什么样

```
插件                                    ×
● 在写代码  window.ps1            02:14
▓▓▓▓░░░░░░░  3/7 项 · 约 4–7 分钟
```

- **第一行**：会话标题（无标题时取第一条用户消息前 18 字）
- **第二行**：状态点 + 当前动作 + 本回合已用时间
- **第三行**：状态条 + 计划进度 + 预计用时

状态点颜色：绿 = 在跑工具，蓝 = 模型在思考，黄 = 等你确认，灰 = 已完成。

## 状态条语义

进度条不表示"完成百分比"，它表示**当前处于哪个阶段**：

| 阶段 | 蓝条 |
|---|---|
| 进行中（跑工具 / 思考） | 循环滑块（1.6 秒一轮） |
| 等你确认 | 卡在 50% |
| 已完成 | 满条 |

计划本身的进度用**文字**表达：`3/7 项`。这样条和字互不干扰——条回答"什么阶段"，字回答"计划到哪"。

## 计划与分支

- 进度分母来自 `todo_write` 的最近一次快照
- 计划项数变化：显示 `计划 3→7`
- 计划内容变化但项数不变：显示 `计划已更新`
- **计时段从最近一次计划变更重新开始**——分支、返工、扩大范围时 ETA 会重算，而不是把整轮已用时间硬减

## 预计用时

- 按**任务类型**（写代码 / 跑测试 / 调研 / 命令…）统计该会话历史回合的耗时
- 显示 `中位数 − 本段已用时间`，并给 P25–P75 区间：`约 4–7 分钟`
- **同类型样本不足 3 轮时不显示**，不猜
- 计划变更后重新计时

## 卡住检测

30 秒没有新事件时，第三行变成 `第 6 步 · 00:45 无动作`。这是实测值，不是估算——它回答"是不是死了"。

## 多会话

- 默认折叠：只显示最近活动的那张，按钮显示 `展开 N`
- 展开后纵向排列，卡片互不重叠（有碰撞检测）
- 每张卡的位置按会话 id 记住；拖动后松手即保存
- 折叠态下其余卡片隐藏但不销毁，展开是瞬时的

## 动作浮层

卡片右侧的竖条按钮（`▸`/`▾`）打开浮层，列出最近 6 步动作：`18:19  写文件 window.ps1`。

- 没有动作记录时按钮自动隐藏，不留空白框
- 浮层靠近屏幕右边缘会自动翻到左侧
- 卡片移动/隐藏时浮层跟随

## 关闭与保留

- 卡片只在三种情况消失：**点 `×`、DSH 重启、会话超过 12 小时无活动**
- 点 `×` 只关闭"这一轮"：同一轮不再出现；该会话开始新一轮时卡片回来
- 完成态保留在桌面上（浅蓝底 + `已完成`），不会自动消失

## 声音

- 任务完成时播放提示音
- 默认 Windows 系统提示音；`cueFile` 可指定自定义音频（wav/mp3）
- 只在状态真正结束（`turn/end`）时响，5 秒冷却

## 运行方式

```
~/.dsh/sessions/*/session.v4.jsonl.zstd
        │ 按 zstd 帧头切开逐帧解压（mtime+size 缓存，文件没变不重解）
        ▼
lib/collect.mjs  还原动作 / 计划 / 用时 / 任务类型
        │ 每 700ms 原子写 state.json
        ▼
window.ps1  PowerShell + WPF 管理 N 个置顶窗口（独占文件锁保证单实例）
```

## 限制

- **仅 Windows**：依赖 PowerShell 5.1 + WPF
- **依赖日志格式**：读 `session.v4.jsonl.zstd`，DSH 改格式会静默失效
- **启发式进度**：没有 todo 清单时只有"第 k 步"，不编百分比
- **不显示子代理**：只看根会话
- **约 0.5–1 秒延迟**：跟随日志刷新

## 隐私

- 只读 `~/.dsh/sessions/`，不写会话数据
- 不联网、无遥测
- 写入 `~/.dsh/work-cards/`：`state.json`、`positions.json`、`dismissed.json`、日志
- `state.json` 含会话标题、命令描述、文件路径——与 DSH 会话日志同级敏感
